# Synthetic contract fixtures

These JSON files contain synthetic contract data, not verified model outputs. `create-case.json` can be posted to the case API. `review-decision.json` illustrates an approval body, but its task ID and state version must be replaced from fresh API reads. `ingest-reply.json` illustrates trusted reply ingest; replace `expected_state_version` from a fresh case read and use an approved contact email from the access file. `server-config.json` is a local setup template with no usable token; follow docs/backend.md to generate credentials outside Git, then add a real token hash. Document and reply assessments remain independent examples against snapshot version 1; do not apply them sequentially without refreshing the version. The referenced document and reply are fictional and are not uploaded assets.

Student 1 uses these for deterministic contract tests and as a starting point for fresh live analysis cases. Student 3 implements matching reply-assessment outputs and sandbox delivery against the case/outbox APIs. Student 2 still implements document assessment. Student 4 can use the case/run/review/outbox/reply/commitment/reminder APIs and these fixtures for isolated UI work. See ../docs/contracts.md for v0.8 states and validation rules, ../docs/communication.md for the labeled sandbox, and ../docs/llm-runtime.md for mandatory live integration. These fixtures are not a substitute for provider calls or deployment tests.
