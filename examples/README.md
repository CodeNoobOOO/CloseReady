# Synthetic contract fixtures

These JSON files contain synthetic contract data, not verified model outputs. `create-case.json` can be posted to the case API. `upload-document.ps1` uploads a local text-based PDF to a freshly read case and polls its durable processing job; the PDF itself must remain outside Git. `review-decision.json` illustrates an approval body, but its task ID and state version must be replaced from fresh API reads. `ingest-reply.json` illustrates trusted reply ingest; replace `expected_state_version` from a fresh case read and use an approved contact email from the access file. `server-config.json` is a local setup template with no usable token; follow docs/backend.md to generate credentials outside Git, then add a real token hash. Document and reply assessments remain independent examples against snapshot version 1; do not apply them sequentially without refreshing the version. The referenced document and reply are fictional.

`run-integrated-demo.ps1` is the complete Student 1–3 sandbox walkthrough. It creates a fresh case, waits for the worker, approves and sandbox-delivers the agent draft, ingests and assesses a synthetic client commitment, then uploads a matching text PDF and verifies readiness. It uses live LLM calls but never sends external email.

Student 1 uses these for deterministic contract tests and as a starting point for fresh live analysis cases. Student 2's extraction and assessment functions now run behind the durable upload API and worker. Student 3 owns reply-assessment outputs and sandbox delivery against the case/outbox APIs. Student 4 can use the case/document/job/run/review/outbox/reply/commitment/reminder APIs and these fixtures for isolated UI work. See ../docs/contracts.md for v1.0 states and validation rules, ../docs/communication.md for the labeled sandbox, and ../docs/llm-runtime.md for mandatory live integration. These fixtures are not a substitute for provider calls or deployment tests.
